# batana-tool 素材采集与标注工具 PRD

> 版本：v1.0（2026-09-20）· 状态：已评审定稿
>
> 服务对象：batana-core（模型训练素材生产）· 采集场景：MacBook + Type-C USB3 双目模组（OV9281，2560×800 side-by-side，120fps 无压缩 MONO8/YUY2），电脑架设在打击区旁，相机正对打击区

## 1. 背景与目标

batana-core 的姿态/轨迹模型需要大量带标注的挥棒素材（M1.5：≥200 段，含真值子集 ≥50 段）。人工逐段录制、命名、裁剪、标注的效率无法支撑该量级。本工具的目标是**采集人只需要站上打击区挥棒，其余全部自动化**：

- 人站上打击区 → 自动识别就位 → 语音提示准备
- 挥棒 → 自动检测、自动分段、自动保存 → 语音提示继续
- 事后（或现场间隙）在图形界面中审核：骨架叠加检查、手动修正关键点、修剪片段、标记合格 → 一键导出为 batana-core 契约格式

## 2. 用户与场景

| 角色 | 场景 |
|---|---|
| 采集员（可为球员本人） | 单人批量采集：站上打击区 → 听语音提示挥棒 → 下一条，连续采集数十段 |
| 标注员 | 素材审核：骨架叠加回放、拖动修正关键点、修剪起止帧、合格性标记、导出训练集 |

采集环境约束（继承拍摄环境调研）：曝光 ≤100µs、击球区补光 ≥10,000 lux、正侧面机位 2–3.5m、架高 1.2–1.5m、相机条水平。

## 3. 功能需求

### F1 双目采集
- UVC 免驱接入，枚举并选择采集模式（2560×800@120 MONO8/YUY2 优先，MJPEG 仅冒烟用并明确警告）
- 左右目切分（SBS 对半），双路独立无损存储（FFV1/MKV 优先，编码不可用时回退并提示）
- 逐帧单调时钟时间戳落盘（CSV：frame_idx, left_ts_ns, right_ts_ns 或 SBS 帧 ts）
- 录制参数随素材保存（分辨率/帧率/格式/曝光/增益）

### F2 打击区 ROI 配置
- 首次使用在预览画面上框选打击区矩形（持久化保存）
- 预览常显 ROI 框与相机水平参考线（辅助调平，水平基线要求）

### F3 就位检测
- ROI 内前景占比超过阈值且稳定 N 帧（默认 1s）判定"已就位"
- 人离开 ROI 超过 M 秒回到空闲态

### F4 语音引导（中文 TTS）
- 状态变化语音："已就位，请准备"→ 倒计时 "3、2、1" →"请挥棒" →"挥棒完成" →"已保存，第 N 段，请准备下一段"；异常（人离开/相机断开/存储失败）有明确提示
- 可全局静音；语音不打断采集流程（异步）
- 实现：macOS 系统 `say`（Tingting 中文语音），零额外依赖；接口抽象便于替换

### F5 挥棒自动检测与分段
- 预录环形缓冲（默认 ≥3s 内存缓冲）
- 挥棒事件：ROI 内帧间运动能量超阈值触发，能量回落且超过后录时长（默认 1s）判结束；片段 = 触发点前 pre-roll（默认 1s）+ 至结束后 post-roll
- 检测失败兜底：手动"开始/结束"按钮全程可用；误检可立即"丢弃重拍"
- 状态机（采集编排）：
  `IDLE（无人）→ READY（就位，语音+倒计时）→ ARMED（待挥棒，预录中）→ SWING（挥棒中）→ SAVING（落盘，语音）→ READY（循环）`
  `任意态 → IDLE（人离开/暂停）`；`任意态 → ERROR（相机/存储异常，语音提示，可恢复）`

### F6 采集会话管理
- 自动编号（采集日期 + 序号）、实时计数（已采集/合格/待审核）
- 暂停/继续；相机断开重连恢复；崩溃恢复（素材索引 JSON 每段落盘即更新）

### F7 骨架自动标注
- MediaPipe Pose（33 关键点，对齐 batana-core pose2d 拓扑与顺序约定），逐帧推理，置信度随帧保存
- 可对左目、右目或双目同时推理（双目为 3D 重建准备）
- 推理在后台线程跑，不阻塞采集

### F8 骨架标定与手动修正
- 回放界面骨架叠加显示（关键点 + 连线，按置信度着色）
- 手动修正：拖动关键点到正确位置，修正点标记 `manual: true` 并保留原自动值
- 批量操作：重跑单帧/整段骨架、删除坏帧、修正撤销
- 相机标定关联：导入 batana-core 标定结果文件（calibration JSON），3D 重建预览（双目素材可查看三角化棒轨迹/骨架点的 3D 投影一致性，辅助判定素材质量）

### F9 片段修剪
- 设置片段起止帧（帧步进微调 + 播放预览），支持左右目同步预览

### F10 素材审核与导出
- 三段式标记：合格 / 不合格 / 待复核；筛选与批量操作
- 导出目录结构（每段一个目录，对齐 session-schema 契约）：
  ```
  sessions/<session_id>/
  ├── session.json      # 对齐 session-schema：meta/video/imu(空)/calibration 引用/pose2d/phases/metrics(空壳)
  ├── left.mkv / right.mkv
  ├── timestamps.csv
  ├── pose2d.json       # 33 点序列 + 置信度 + manual 标记
  └── capture_meta.json # 采集参数（模式/曝光/增益/相机型号/标定文件 hash）
  ```
- 导出前自动校验（内置契约必填项校验；本机存在 batana-core 仓时可选调用其 validate_session.py 全量校验）
- 不合格素材不进入导出集（保留原盘可恢复）

## 4. 非功能需求

- 120fps 双目流下 UI 不卡：采集线程与 UI 分离，预览降频（30fps 显示），编码落盘在 worker 线程
- 存储：训练素材默认无损（FFV1）；磁盘占用预估显示（120fps mono 双目 ≈ 每分钟 X GB，按模式实测）
- 崩溃恢复：断电/崩溃后已保存段不丢、索引可重建
- 可测试性：所有非 UI 逻辑（状态机/检测/存储/导出）不依赖相机与 GUI，支持视频文件回放作为合成数据源端到端测试

## 5. 技术方案

- **PySide6**（Qt for Python）：桌面 GUI，与 batana-core 同语言栈，标定/3D 工具可直接复用（batana-core `tools/` 以路径依赖或源码引用方式集成）
- OpenCV（采集/切分/检测/编码）、MediaPipe Tasks（骨架）、numpy
- 线程模型：`CaptureThread`（UVC 抓帧 + 环缓冲 + 检测事件）→ `EncodeWorker`（落盘）→ `PoseWorker`（骨架）→ Qt 主线程（UI/语音）
- 语音：subprocess 调 macOS `say -v Tingting`，队列化避免重叠


## 7. 验收标准

1. 合成视频源端到端：喂入"无人→人入场→挥棒→离场"合成双目视频，状态机按预期迁移，产出 ≥1 段完整素材目录并通过导出校验
2. 单元测试：状态机全迁移路径、挥棒检测（含误检/漏检边界）、环缓冲边界、导出契约校验，pytest 全绿
3. 骨架手动修正：拖动修正 → 保存 → 重新加载后修正值与 manual 标记保持
4. UI 冒烟：采集页/审核页可启动（离屏渲染测试）

## 8. 边界（本工具不做）

- 不做模型训练与正式评分（batana-core 职责）
- 不做云同步（batana-web/sync-api 职责，导出目录由后续流程上传）
- 不做 IMU/cap 数据融合采集（P2b 后另行扩展）
- 不做 Android/iOS（仅 macOS；Windows/Linux 按 PySide6 可移植性预留但不验收）

## 9. 里程碑

- v0.1（MVP）：F1–F6、F10 基础导出（无骨架）——支撑 M1.5 视频素材批量采集
- v0.2：F7–F9 骨架自动标注 + 手动修正 + 修剪——支撑标注素材生产
- v0.3：批量导出与真值子集工具（雷达枪读数录入、子集筛选）、3D 质量预览
